# INFRA — инфраструктура проекта CLAW

Карта связей (кто с кем говорит):

```
[ESP32 + PCA9685 + BMI160] --USB Serial 921600--> [helper-ПК]
                                                            |
                                                  socat TCP:5000 (по команде)
                                                            |
                       [моя песочница] --TCP--> [сеть 192.168.x.x] --/
                              |
                    git origin + git github
```

## 1. Железо (робот)

- ESP32 (контроллер), PCA9685 (сервы, I2C 21/22), BMI160 (IMU, та же I2C),
  ST7789 (дисплей, SPI), ручной пульт (пины 25/26/32/33).
- Консоль: Serial 921600 (`SERIAL_BAUD`), G-code построчно.
- Питание серв — отдельно от ESP32 (см. шапку `main.cpp`).

## 2. Машина helper (рядом с железом)

- Хост `spell@helper`, каталог `~/Documents/PlatformIO/6dof-2026`
  (PlatformIO + VS Code; там же клон репозитория).
- USB-порты прыгают (`ttyUSB0`/`ttyUSB1`) — сверять `ls /dev/ttyUSB*`
  и `dmesg` после каждого перетыкания.
- TCP-мост под ручным управлением (включать только на сессию!):
  ```bash
  # освободить порт (закрыть монитор/скрипты!), затем:
  socat TCP-LISTEN:5000,fork,reuseaddr /dev/ttyUSB1,raw,echo=0,b921600
  # проверка вторым терминалом:
  echo "M105" | nc localhost 5000   # в ответ Angles:...
  ```
- Скорость моста обязана совпадать с `SERIAL_BAUD`, иначе мусор/молчание.
- Хозяин порта всегда один: мост ИЛИ монитор ИЛИ скрипт.

## 3. Сеть

- Известные адреса мостов: `192.168.99.6:5000`, `192.168.2.56:5000`
  (меняются — актуальный уточнять у helper перед сессией).
- Диагностика маршрута из песочницы: TCP-handshake (`nc`/сокет),
  затем `M105` с таймаутом. `TIMEOUT` при открытом TCP = мост жив,
  молчит контроллер (бодрейт? чужой tty? завис?).

## 4. Репозитории

- `origin`: `http://192.168.2.6:20080/cpp/6dof-2026.git`
  (локальный git-хост, доступ по токену; токены в чат — только
  одноразово, в репозиторий — НИКОГДА, в URL — только `xxxxx`).
- `github`: `SpellcasterMom/test.git` — зеркало, пуш **только**
  по явной команде (`git push github master`).
- Дисциплина: работа в ветках, в `master` принятое на железе,
  слияние по команде; несколько машин — `fetch` перед `push`.

## 5. Моя песочница (где работает агент)

- Контейнер: `172.31.0.2/16`, шлюз `.1`; наружу ходит
  (github, реестр PlatformIO), внутрь 192.168.x.x — есть маршрут.
- Есть: `python3` (только stdlib — `pip`/`pyserial`/`ssh` НЕТ),
  `nc`, `wget`, pandoc 3.6.4 в `/tmp/mywork` (переживёт ли
  перезапуск — неизвестно, при потере скачать заново).
- Нет: тулчейна ESP32 (сборка — на helper), прямого Serial,
  просмотра видео (только файлы-кадры), LibreOffice/Visio.
- G-code по TCP: `tools/tcp_console.py HOST PORT ["CMD"]`
  (таймауты с запасом, эхо `"> "` режется, `OK`/`OK:`/`ERROR`).
- Протокол совместной работы: один хозяин порта (я ИЛИ helper);
  движения — только с наблюдателем у руки; логи прогонов
  в репо не коммитим.
